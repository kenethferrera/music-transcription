1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
A complete, maintainable, production-ready web application has been implemented
in full accordance with the project specification (music_transcription_claude_implementation_prompt.txt).
The application takes an uploaded song (MP3, WAV, FLAC, OGG, M4A) and executes a
9-stage automated pipeline:
  1. Upload verification (Cloudflare R2 object storage)
  2. Audio preprocessing (FFmpeg / soundfile probing)
  3. Source separation using Demucs (htdemucs 4-stem: vocals, drums, bass, other)
  4. Musical transcription using MuScriptor Large (MT3_FULL_PLUS 36 categories)
  5. External lyrics recognition using cloud STT API (Groq/OpenAI/Deepgram/Mock)
  6. Non-AI lyric-to-note alignment (syllable segmentation, melisma, note binding)
  7. Non-AI musical analysis (Krumhansl-Schmuckler key, chroma chords, tempo, meter)
  8. Canonical arrangement assembly (note deduplication, track grouping)
  9. Export preparation (MIDI Type 1, Karaoke .kar, MusicXML 4.0, full-score & lead-sheet PDF)

STRICT MODEL RESTRICTIONS OBSERVED:
  - Source separation: Demucs ONLY (htdemucs checkpoint).
  - Music transcription: MuScriptor Large ONLY (MuScriptor/muscriptor-large).
  - Lyrics recognition: External cloud STT API ONLY. No local Whisper models installed.
  - Chords, key, tempo, meter, lyric alignment: 100% Non-AI signal processing and music theory.
  - Persistent storage: Cloudflare R2 production adapter via standard boto3 S3 API.
  - Database persistence: SQLAlchemy ORM supporting PostgreSQL in production and SQLite in dev.

[A] CANONICAL MUSIC SCHEMA & CONTRACTS
--------------------------------------------------------------------------------
- shared/music_schema/arrangement.py:
  Pydantic v2 data models for the single source of truth across all exports:
  - NoteEvent: id, track_id, pitch (0-127), start_time, duration, velocity (1-127), confidence, source_stem, is_edited.
  - LyricEvent: id, text, start_time, duration, note_id, syllable_type (single, begin, middle, end), confidence.
  - ChordEvent: id, symbol (e.g. C, Am7, G/B), root, quality (maj, min, 7, m7, dim, aug), start_time, duration.
  - TempoEvent: start_time, bpm, confidence.
  - TimeSignatureEvent: start_time, numerator, denominator.
  - KeySignatureEvent: start_time, key, mode (major/minor).
  - Track: id, name, family (InstrumentFamily), midi_program (0-127), is_percussion, color, volume, pan, muted, solo, notes list.
  - ProjectMetadata: project_id, title, artist, original_filename, audio_format, duration_seconds, sample_rate, channels, created_at.
  - Arrangement: Full composition holding metadata, tempo map, time signatures, key signatures, chords, lyrics, tracks, stem references.

- shared/processing_contracts/jobs.py:
  Pipeline contracts: JobStage (9 distinct stages), JobStatus (pending, processing, success, failed), StageProgress, JobProgressEvent.

[F] ARRANGEMENT & NON-AI MUSICAL ANALYSIS WORKERS
--------------------------------------------------------------------------------
- workers/arrangement/music_analyzer.py:
  100% Non-AI signal processing and music theory algorithms:
  - Tempo & Beat Grid: librosa.beat.beat_track and onset envelope autocorrelation.
  - Key Signature: Krumhansl-Schmuckler chroma correlation with 12 major and 12 minor tonal profiles.
  - Chord Recognition: 12-pitch class chroma template matching for Major, Minor, 7th, m7, Dim, Aug, Sus4 triads across windowed time frames, reinforced by polyphonic note pitch class sets.
  - Time Signature: Periodicity autocorrelation of downbeat energies (defaulting to 4/4).

- workers/arrangement/lyric_aligner.py:
  Non-AI lyric-to-note alignment component:
  - Rule-based vowel-nuclei syllabification.
  - Associates syllables and words with transcribed vocal melody notes.
  - Handles melisma (one syllable across multiple notes) and multi-syllable word timing.

- workers/arrangement/reconciler.py:
  ArrangementReconciler component:
  - Reconciles notes from mix and stems.
  - Deduplicates overlapping notes on same pitch within tolerance window (delta_t <= 40ms).
  - Prioritizes isolated vocal stem evidence for vocal melody and bass stem for bassline.
  - Groups notes into tracks and outputs the canonical Arrangement object.


[G] EXPORT WORKERS
--------------------------------------------------------------------------------
- workers/export/midi_exporter.py:
  Exports Standard MIDI File Type 1 (.mid) via mido:
  - Track 0: Conductor track with track name, tempo events (bpm2tempo), time signature, and key signature meta-messages.
  - Separate instrument tracks for Vocals, Piano, Guitar, Bass, Drums (channel 10 / 9 0-indexed), Strings, Other.
  - Program change messages, note-on and note-off delta ticks, velocity preservation.

- workers/export/karaoke_exporter.py:
  Exports Karaoke MIDI (.kar) file:
  - Conductor track with @TTitle, @TArtist, @KMIDI KARAOKE FILE, @LENGL.
  - Vocal melody track containing synchronized lyric meta-events ('\' for paragraph, '/' for line, space for word boundary) aligned at the exact tick position of vocal melody notes.
  - Accompaniment tracks for backing instruments.

- workers/export/musicxml_exporter.py:
  Exports standards-compliant MusicXML 4.0:
  - Full Score: All active transcribed parts with proper clefs (treble, bass, percussion), key signature fifths, time signature beats, divisions, measures, notes, rests, chords, lyrics with <syllabic> and <text>.
  - Lead Sheet: Single vocal melody stave with lyrics aligned under notes and chord symbols (<harmony><root><kind>) engraved above the stave.

- workers/export/pdf_exporter.py:
  Exports vector-grade sheet music PDF:
  - Verovio toolkit integration rendering MusicXML to SVG, followed by CairoSVG conversion to vector PDF.
  - Pure Python PDF 1.4 vector generator fallback with staves, clefs, bar lines, and metadata.

4. VERIFIED MODEL INTERFACES & TECHNICAL SPECIFICATIONS
================================================================================

[A] DEMUCS (Meta)
  - Repository: facebookresearch/demucs
  - Model: htdemucs (Hybrid Transformer Demucs v4)
  - Audio Input: 44.1 kHz stereo audio
  - Stems Generated: Exactly 4 stems: vocals, drums, bass, other
  - Memory: ~1.5 - 2.0 GB VRAM with chunking (7.8s chunks, 0.25 overlap)
  - License: MIT License
  - Verified Limitation: Standard Demucs does not isolate acoustic piano or guitar individually. Piano and guitar reside in the 'other' stem. Stems are not labeled as individual acoustic instruments.

[B] MUSCRIPTOR LARGE (Kyutai & Mirelo)
  - Hub: MuScriptor/muscriptor-large (Hugging Face)
  - Parameters: ~1.3 Billion parameters
  - Audio Input: Resampled internally to 16 kHz mono
  - Output Events: Yields ProgressEvent, NoteStartEvent(pitch, start_time, index, instrument), and NoteEndEvent(end_time, start_event).
  - Instrument Taxonomy: MT3_FULL_PLUS 36 instrument categories (including piano, guitar, bass, drums, strings, brass, voice/choir).
  - Velocity: Does NOT predict velocity directly in tokens. Velocity is calculated from onset audio RMS energy.
  - License: CC BY-NC 4.0 (requires Hugging Face token HF_TOKEN to accept license).
  - Hardware: Requires ~4.5 - 6 GB VRAM in fp16. To prevent OOM on 8GB GPUs, Demucs and MuScriptor are scheduled sequentially with torch.cuda.empty_cache().

[C] EXTERNAL STT API (Cloud Only)
  - Providers Supported: Groq Whisper API (whisper-large-v3), OpenAI Whisper API (whisper-1), Deepgram (nova-2), MockSTTProvider.
  - Input: Demucs isolated vocal stem (vocals.wav).
  - Word Timestamps: Extracted and normalized into common STTWord format.
  - Strictly No Local Weights: No local Whisper or Whisper.cpp installed.
